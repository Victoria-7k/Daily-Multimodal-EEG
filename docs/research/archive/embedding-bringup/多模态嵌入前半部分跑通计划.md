# Daily Multimodal 多模态嵌入前半部分跑通计划

> **目标：** 跑通皮肤电、PPG、加速度、面部录像、录音、脑电的多模态信号编码流程，完成图中任务的前半部分：从原始多模态数据到可复现、可替换、可训练的窗口级 embedding 工程；只做轻量 baseline 验收，不进入后半部分脑电教师模型微调和知识蒸馏。

**核心原则：** 先完成基础闭环，再尝试进阶模型；所有高级模型都是可替换插件，不是前置依赖。每次只升级一个模态或一个融合模块，并和基础版在同一数据切分、同一指标下对照。进阶模型效果不好、成本过高或稳定性差时，立即回退到基础版，不阻塞主流水线。

**总体思路：** 以每条情绪评分事件为中心，用 `absolute_onset_time` 做跨模态绝对时间对齐；EEG 使用 `RecordingStartTime + onset` 校验相对时间；PPG/GSR/ACC 使用 CSV 内绝对时间列切窗并合成为统一 `wear_emb`；视频与录音使用同日期 MP4 及其音频流切片。第一版先完成 manifest、window index、单样本切窗、单样本基础 embedding、10 条样本 smoke test、单被试测试，再扩大到完整可用样本集。后续才逐步替换为 LaBraM/EEGPT、PatchTST/TS2Vec、OpenFace temporal Transformer、WavLM + openSMILE 和 modality Transformer。

**技术栈建议：** Python 3.10+、PyTorch、MNE、pandas/numpy/scipy、opencv/ffmpeg/ffprobe、torchaudio、transformers、OpenFace 或等价面部特征提取工具、openSMILE、pytest、YAML 配置。

### 3.3 模型升级和回退契约

所有模态都遵循三级制：

```text
基础版：必须先跑通，作为默认回退点。
进阶版：基础版通过后再替换，且一次只替换一个模态或一个融合模块。
实验版：只有进阶版有效且稳定后再尝试。
```

升级前必须保留基础版输出和指标。进阶版只有在同一 subject split、同一评价指标下优于基础版，且失败率、运行时间、显存占用可接受时，才进入主线。否则记录实验结果并回退基础版。

### 阶段 2：构建只读 manifest（已完成）

**目标：** 不读取大文件内容，只通过路径、JSON、TSV、文件名和时间戳生成事件级 manifest。

输入：

- EEG JSON：读取 `RecordingStartTime`、`RecordingDuration`、`SamplingFrequency`
- 评分 TSV：读取 `onset`、`duration`、`absolute_onset_time`、情绪标签列
- 穿戴文件名：解析 `start/end/modality`
- 视频目录：解析 `subN/MMDD`，先做日期级候选匹配

输出：

```text

outputs/reports/manifest_coverage.json
outputs/reports/manifest_summary.json
```

说明：后续如服务器补齐 `pandas` 和 `pyarrow`，同一份 manifest 可以再转为 parquet；当前主线以已跑通的 JSONL 为准。

验收标准：

- manifest 行数应为 1272。
- 完整 ACC/GSR/PPG 覆盖事件数应接近已巡检值 1127。
- 视频日期覆盖事件数应接近已巡检值 1103。
- 完整多模态候选事件数应接近已巡检值 995。

### 阶段 3：视频、音频精确时间对齐

**目标：** 从日期级视频候选进一步定位到覆盖评分窗口的 MP4 文件，并明确 MP4 内音轨是否可用。

步骤：

1. 对每个候选 MP4 调用 `ffprobe`。
2. 读取 `creation_time`、`duration`、音频流、采样率和声道数。
3. 将 `creation_time` 从 UTC 转为 `Asia/Shanghai`。
4. 判断 MP4 时间段是否覆盖评分事件窗口。
5. 对跨多个 MP4 的窗口，记录多个候选片段和相对切片时间。

输出：

```text
outputs/manifests/events_manifest_with_video_audio.jsonl
outputs/reports/video_audio_alignment_report.json
```

验收标准：

- 每条有视频日期的事件都能得到 `video_candidates` 字段。
- 每个候选 MP4 记录 `mp4_path`、`mp4_start_time`、`mp4_end_time`、`clip_start_seconds`、`clip_end_seconds`、`has_audio_stream`。
- 抽样 10 条事件，人工检查 EEG 时间、评分时间、视频时间是否落在合理时段。

### 阶段 4：生成 window index 与单事件切窗探针

**目标：** 把事件级 manifest 转成统一窗口样本表，并选一条完整多模态事件完成所有模态切窗，不训练模型。

第一版窗口策略：

```text
基础闭环：每个事件先取评分前 [-10s, 0s] 单窗口。
扩展窗口：基础闭环通过后，在 [-60s, 0s] 内使用 10s window、5s stride。
```

输出：

```text
outputs/window_index/window_index.jsonl
outputs/reports/probe_one_event.json
outputs/reports/probe_one_event_shapes.txt
```

验收标准：

- `sample_id` 稳定，例如 `sub-02_ses-03_event-0012_win-0000`。
- EEG 切窗 shape 稳定，重采样后 10 秒窗口为 `[C, 2500]`。
- PPG/GSR/ACC 切窗非空，时间段落在对应 CSV 内。
- 视频片段能定位到 MP4 内相对时间。
- 音频 waveform 能正常抽取并重采样到 16 kHz。
- 所有切窗都来自原始数据，只写入 `wzw` 下的报告或临时输出。

### 阶段 5：基础版单事件 embedding smoke test

**目标：** 对阶段 4 的同一条窗口输出统一 embedding，不追求高性能，只验证工程闭环和数据契约。

基础版编码器：

- EEG：MNE 读取 BDF，notch、1-45 Hz bandpass、250 Hz 重采样，接 EEGNet / 1D-CNN / shallow Transformer，输出 `eeg_emb [256]`。
- Wear：PPG + GSR + ACC 联合统计特征，接 MLP，输出 `wear_emb [256]`。
- Face：OpenFace 直接处理 MP4 得到 CSV，窗口内统计 AU、head pose、gaze、face missing ratio，接 MLP，输出 `face_emb [256]`。
- Audio：MP4/AAC 抽 mono 16 kHz wav，WavLM 或 wav2vec2 mean pooling，接 projection，输出 `audio_emb [256]`。

输出：

```text
outputs/embeddings/one_event_embeddings.npz
outputs/reports/one_event_embedding_report.json
```

验收标准：

- `eeg_emb`、`wear_emb`、`face_emb`、`audio_emb` 均为 `[256]`。
- `modality_mask` 正确标记存在模态。
- 没有 NaN。
- 只有缺失模态允许全 0，且必须 `modality_mask=0`。
- 输出包含 `sample_id`、`event_id`、标签、源路径、encoder 版本。

### 阶段 6：10 条事件基础 embedding 小规模测试

**目标：** 验证批处理、异常处理、日志、输出格式和基础 encoder 的稳定性。

运行范围：

- 从完整多模态候选事件中取 10 条。
- 尽量覆盖不同被试、不同日期、不同视频文件数量。
- 第一轮每个事件只取一个 `[-10s, 0s]` 窗口。

输出：

```text
outputs/embeddings/smoke_10_events_basic_embeddings.npz
outputs/logs/smoke_10_events_basic.log
outputs/reports/smoke_10_events_basic_report.json
```

验收标准：

- 10 条事件全部完成或明确记录失败原因。
- 每个成功窗口的 embedding shape 一致。
- 日志中每个失败窗口都有 `sample_id`、模态、路径和异常类型。
- 输出可由 `fusion.pack_embeddings` 直接读取。

### 阶段 7：单被试基础闭环测试

**目标：** 选择一个覆盖较好的被试，跑完该被试所有可用评分事件，确认跨日期、跨 session、跨视频文件的稳定性。

建议优先被试：

- `sub-10`：评分行 103，视频日期覆盖 103，穿戴三模态覆盖 103。
- `sub-14`：评分行 103，视频日期覆盖 103，穿戴三模态覆盖 103。


验收标准：

- 单被试窗口级 embedding 全部可加载。
- 每个模态缺失率为 0 或有明确原因。
- 运行时间、显存占用、失败清单被记录。

## 5. 模态处理细节

### 5.1 EEG

对齐依据：

- `RecordingStartTime`
- `onset`
- `absolute_onset_time`

处理原则：

- 以 `absolute_onset_time` 为主，使用 `RecordingStartTime + onset` 做一致性校验。
- 不同采样率统一重采样到 `250 Hz`。
- 第一版只做必要滤波、坏段检查和固定窗口裁剪，不做复杂清洗。
- 10 秒窗口在 250 Hz 下输入形状为 `[channels, 2500]`。
- 基础版 encoder 使用 EEGNet / 1D-CNN / shallow Transformer，输出 `eeg_emb [256]`。
- 进阶版再尝试 LaBraM / EEGPT frozen encoder，只训练 projection head。
- 实验版才尝试解冻最后 1-2 层、adapter 或 LoRA。
- 不做全量微调作为第一选择，因为只有 15 个被试，过拟合风险很高。

输出建议：

```text
eeg_emb: float32[num_windows, 256]
```

回退点：

```text
MNE + 250 Hz + EEGNet/1D-CNN/shallow Transformer
```

### 5.2 Wearable：PPG + GSR + ACC 联合处理

对齐依据：

- PPG：`csv_time_PPG`
- GSR：`csv_time_GSR`
- ACC：`csv_time_motion`

处理原则：

- 用绝对时间切评分前窗口。
- PPG、GSR、ACC 来自同一批 wearable 记录，第一版不分散成三个最终 embedding，而是合成为一个 `wear_emb`。
- PPG 容易被运动伪影污染，ACC 用于判断运动强度和稳定性；GSR 提供交感神经唤醒相关信号。
- 基础版提取 handcrafted/statistical features 后接 MLP，输出 `wear_emb [256]`。
- 进阶版再尝试 raw sequence encoder，例如 TCN / PatchTST / TS2Vec，并和 handcrafted features 拼接。
- 中间层可以保留 `ppg_features`、`gsr_features`、`acc_features` 和质量指标，便于排错和消融。

基础版特征建议：

```text
PPG:
ppg_mean, ppg_std, ppg_min, ppg_max, ppg_slope,
heart_rate_mean, heart_rate_std, peak_count,
peak_interval_mean, peak_interval_std, signal_quality

GSR:
gsr_mean, gsr_std, gsr_min, gsr_max, gsr_slope,
tonic_mean, phasic_mean, scr_count,
scr_amplitude_mean, scr_amplitude_max

ACC:
acc_x_mean/std, acc_y_mean/std, acc_z_mean/std,
acc_norm_mean, acc_norm_std, acc_energy,
acc_motion_intensity, acc_stationary_ratio
```

输出建议：

```text
wear_emb: float32[num_windows, 256]
wear_quality: float32[num_windows, K]
```

回退点：

```text
PPG/GSR/ACC 统计特征 + MLP
```

### 5.3 面部录像

对齐依据：

- 视频目录：`subN/MMDD`
- MP4 元信息：`creation_time + duration`
- 评分事件：`absolute_onset_time`

处理原则：

- 先用 `ffprobe` 建立 MP4 时间索引。
- 第一版不要逐帧保存图像，也不要直接全量跑 VideoMAE。
- 使用 OpenFace 直接处理 MP4，保存 CSV。
- 按 window index 从 OpenFace CSV 中切片，统计 AU、head pose、gaze、landmark 质量、face confidence、success flag。
- 基础版使用窗口统计特征 + MLP，输出 `face_emb [256]`。
- 进阶版使用 frame-level OpenFace features + GRU / temporal Transformer。
- 实验版才考虑 VideoMAE 或 face crop 视频模型。

缓存建议：

```text
outputs/cache/face/openface/sub-02/date/video_name.csv
```

输出建议：

```text
face_emb: float32[num_windows, 256]
face_quality: face_missing_ratio, mean_confidence
```

回退点：

```text
OpenFace CSV 统计特征 + MLP
```

### 5.4 录音

对齐依据：

- 优先使用 MP4 内音频流。
- 对有独立 `.AAC` 的日期，作为辅助候选，但第一版先以 MP4 内音轨为主。

处理原则：

- 从覆盖事件窗口的 MP4 中抽取音频。
- 统一转为 mono、16 kHz、wav。
- 基础版优先使用 WavLM mean pooling；若环境或权重不可用，可回退 wav2vec2 mean pooling。
- 进阶版增加 openSMILE eGeMAPS 特征，再和 WavLM embedding 拼接后投影到 `audio_emb [256]`。
- openSMILE 不阻塞第一版闭环；没有 openSMILE 时先保留 WavLM/wav2vec2 基础版。

抽取命令示例：

```bash
ffmpeg -i input.MP4 -vn -ac 1 -ar 16000 output.wav
```

输出建议：

```text
audio_emb: float32[num_windows, 256]
audio_quality: duration_sec, rms_energy, has_voice_optional
```

回退点：

```text
WavLM 或 wav2vec2 mean pooling + projection
```

### 5.5 融合与基础 baseline

融合输入：

```python
x = torch.cat([eeg_emb, wear_emb, face_emb, audio_emb], dim=-1)
```

输入形状：

```text
x.shape = [B, 1024]
```

基础 baseline：

```text
[eeg_emb, wear_emb, face_emb, audio_emb]
-> concat
-> MLP
-> emotion prediction
```

进阶融合：

```text
tokens = torch.stack([eeg_emb, wear_emb, face_emb, audio_emb], dim=1)
tokens.shape = [B, 4, 256]
modality_mask.shape = [B, 4]

4 个模态 token
-> Transformer Encoder
-> mean pooling / CLS token
-> classifier / regressor
```

如果 concat + MLP 都跑不起来，不优先换复杂结构，先检查时间对齐、标签、窗口、mask 和数据质量。

## 7. 风险与处理策略

### 7.1 视频时区风险

风险：MP4 `creation_time` 是 UTC，评分时间是本地时间。

处理：

- 统一将 MP4 `creation_time` 转为 `Asia/Shanghai`。
- 抽样检查若干事件的 EEG 时间、评分时间、视频时间是否落在同一日同一时段。

### 7.2 穿戴数据跨天风险

风险：穿戴文件名中的开始和结束时间可能跨天，不能只按日期匹配。

处理：

- 必须按绝对时间 interval 匹配。
- 同一天多段穿戴记录时选择覆盖评分窗口的那一段。

### 7.3 sub-01 缺视频

风险：sub-01 无法用于完整视频多模态。

处理：

- 完整多模态第一版排除 sub-01。
- 保留 sub-01 的 EEG + PPG/GSR/ACC + 音频/视频缺失 mask，用于后续缺模态实验。

### 7.4 EEG 多采样率

风险：不同采样率会造成模型输入长度不一致。

处理：

- 第一版统一重采样到 250 Hz。
- manifest 记录原始采样率。

### 7.5 大文件运行时间风险

风险：视频和 BDF 文件很大，直接全量跑会耗时且难定位错误。

处理：

- 严格执行单事件、10 事件、单被试、全量基础 embedding 四级测试。
- 每一级都生成报告后再进入下一级。

### 7.6 高级模型过早介入风险

风险：一开始就上 LaBraM/EEGPT、VideoMAE、cross-attention 或蒸馏，容易把数据对齐、标签、窗口、mask 的问题误判成模型能力问题。

处理：

- 先完成基础版 embedding 和 concat MLP baseline。
- 进阶模型一次只替换一个模块。
- 进阶模型必须和基础版在同一 subject split 下对照。
- 指标不升、失败率增加或成本不可接受时，回退基础版。

### 7.7 subject leakage 风险

风险：按窗口随机切分训练集和测试集会让同一被试的相邻窗口同时出现在训练和测试中，导致指标虚高。

处理：

- baseline 和所有进阶模型实验必须按 subject split。
- 随机窗口切分只能用于调试小批量过拟合，不能用于最终结果报告。
- 后续资源允许时再做 leave-one-subject-out 稳健性验证。
